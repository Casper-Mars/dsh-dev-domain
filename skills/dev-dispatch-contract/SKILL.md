# 派发契约（固件）

本 Skill 是固件：随 `dsh-dev-domain` 发布，只读，不参与进化。

## 上下文卡片（必须字段）

派发时按下列顺序组织内容，字段缺失要在派发前补齐或向用户确认：

1. **任务编号与名称**：与任务清单一致，便于回查。
2. **背景**：为什么要做，关联的文档 / Issue / 会话结论。
3. **目标**：一句话说清交付物是什么。
4. **验收标准**：逐条可验证，禁止「体验良好」这类无法判定的描述。
5. **路径与仓库**：项目绝对路径、目标分支、worktree 路径。
6. **约束**：只读目录、禁止 push、禁止改动的模块、必须使用的工具/版本。
7. **交付格式**：分支与 commit、执行命令与退出码、逐条验收证据、未覆盖项。

## 派发参数

- `agent_preset`：编码用 `dev-developer`，验证用 `dev-tester`。
- `mode: run`，并设置足够的超时（长任务建议 7200 秒）。
- 子 agent 的 `maxDepth` 为 1：它不能再向下派发，复杂任务由 Leader 拆成多个。

## 返回约定

子 agent 的汇报必须包含：

- 分支名 + commit hash；
- 实际执行的命令与退出码；
- 逐条验收标准的证据（文件 / 命令输出 / 测试结果）；
- 未覆盖项与风险；
- 如有阻塞，明确说明卡在哪一步、需要 Leader 做什么决策。

## 禁止行为

- 禁止只给一句「按需求实现」就派发。
- 禁止把多个互不相关的任务塞进同一次派发。
- 禁止在子 agent 返回「完成」后不做完整性 triage 就转交 Tester。
