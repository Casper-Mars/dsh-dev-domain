# 质量闸门（固件）

本 Skill 是固件：随 `dsh-dev-domain` 发布，只读，不参与进化。

## 三维检查

| 维度 | 检查内容 |
|------|----------|
| 内容 | 功能完整准确；验收标准逐条命中；无遗漏、无越界改动 |
| 格式 | 代码规范；类型检查通过；测试通过；产物可运行 / 可安装 |
| 逻辑 | 边界与失败路径覆盖；无隐藏耦合；错误信息可定位 |

## 证据门槛

任何一条验收标准都必须有一条可复现的证据，优先级从高到低：

1. 命令 + 退出码（例如 `pnpm typecheck` → 0）；
2. 测试输出（用例名 + 通过数）；
3. 文件内容 / 目录结构（路径 + 关键片段）；
4. 运行时状态快照（例如 `--dump-config` 输出）。

「子 agent 说通过了」不构成证据。

## 打回条件

出现下列任一情况必须打回，不得带病交付：

- 验收标准有未解释的缺口；
- 类型检查或测试失败；
- 引入了任务范围外的改动；
- 证据无法复现，或退出码与结论矛盾；
- 同类低级错误重复出现。

## 交付声明

交付回复固定包含：分支 + commit、命令与退出码、逐条验收结果、未覆盖项 / 风险。
未覆盖项必须显式列出，不允许用「应该没问题」代替。
