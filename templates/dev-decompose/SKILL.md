# 需求拆解

## 目标

把「一个模糊的大需求」变成「一组可独立验收、可并行或串行执行的任务」。

## 步骤

1. **提取结果物**：用户最终要拿到什么（可运行的系统、文档、数据、发布物）。
2. **列出验收标准**：每条都要能被命令、文件或运行时状态验证。
3. **切分任务**：按「一次交付一个可验证增量」切，避免跨模块大爆炸改动。
4. **标注依赖**：画出任务 DAG，明确哪些必须串行、哪些可以并行。
5. **定优先级**：P0 阻塞项优先；有依赖的先做上游。
6. **写任务卡片**：编号、名称、背景、目标、验收标准、路径、约束、执行者。

## 拆分质量判据

- 单个任务能在一次子 agent 会话内完成；
- 每个任务都有独立、可复现的验收方式；
- 任务之间接口清晰，不出现「改同一个文件的两半」；
- 不把「调研」和「实现」混在同一个任务里。

## 反模式

- 按代码文件拆而不是按交付增量拆；
- 验收标准写成「功能正常」；
- 任务过大导致子 agent 超时或中途丢失上下文；
- 依赖未标注，导致并行任务互相覆盖。
