# 任务复盘

## 什么时候复盘

- 任务交付后（无论成败）；
- 同一类失败第二次出现；
- 某个做法被反复证明有效，值得沉淀。

## 步骤

1. **收集事实**：时间、输入、预期、实际、命令输出；不写主观感受。
2. **归因**：把偏差落到具体环节（需求、拆解、派发、编码、验证、环境）。
3. **提出改进**：一次只改一个变量，写清预期影响与回滚方式。
4. **预注册判据**：动手前写定验证指标与观察窗口，事后不调整。
5. **验证**：按预注册口径执行；达标保留，不达标回滚。
6. **沉淀**：有效做法写进对应 Skill / 规则；无效尝试保留负结果，避免重复踩坑。

## 复盘输出模板

- 做得好的（可复用）
- 出问题的（根因 + 证据）
- 下一次只改的一件事
- 需要更新哪个资产（Skill / 规则 / 测试）

## 纪律

- 不追责个人，只追流程与资产；
- 没有证据的归因不算归因；
- 一轮只改一个变量，否则无法判断改进是否有效。
